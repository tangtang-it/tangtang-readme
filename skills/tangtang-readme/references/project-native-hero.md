# 糖糖it项目原生Hero设计指南

> 作者：糖糖it

---

## 一、设计原点：从项目5个事实出发

好的Hero不是装饰，而是项目本身的视觉浓缩。设计前必须先回答以下5个问题：

### 1. 项目类别
这个项目是什么类型？
- 基础设施/工具库
- 研究论文/数据库
- 编程语言/编译器
- 创意工具/设计系统
- 文档/知识项目
- 应用/服务

### 2. 主要用户
谁会第一眼看这个README？
- 工程师/开发者
- 研究者/学生
- 设计师/创作者
- 产品经理/用户
- 开源贡献者

### 3. 主要动作
用户看完Hero后最可能做什么？
- `npm install` / `go get`
- 阅读文档
- Star收藏
- 看Demo
- Fork参与
- 复制代码片段

### 4. 最佳证明
什么最能说明这个项目有用/厉害？
- 代码片段
- 终端输出截图
- 架构图
- 生成的样例
- Benchmark数据
- Star数/下载量
- 谁在用

### 5. 原生视觉素材
项目已经有什么不需要额外设计的东西？
- Logo
- 代码片段
- 命令行输出
- 生成的文件
- 界面截图
- 图标
- 终端配色

## 二、Hero的5个组成部分

一个完整的项目原生Hero包含且仅包含以下元素：

### 1. 类别/技术上下文
- 一两个词说明这是什么东西
- 例如：`Go CLI Tool` · `React Component Library` · `Rust Database`
- 不要写slogan，写分类

### 2. 仓库名
- 项目的名字，清晰可读
- 如果名字有特殊含义，可以在旁边小字标注
- 不要加多余装饰

### 3. 具体描述
- 一句话说清楚这个项目做什么、解决什么问题
- 避免"高性能"、"现代"、"优雅"这类空话
- 要说具体："在10ms内把Markdown转成HTML"而不是"高性能Markdown处理器"

### 4. 真实项目素材
- 从第5个事实里选的原生素材
- 不要用通用插画、3D小人、stock photo
- 必须是项目本身产出的东西：代码、输出、截图、生成结果

### 5. 小仓库元数据
- 不超过3个关键指标
- 例如：版本号、Star数、License、CI状态、Bundle大小
- 小字号，放在角落，不抢注意力

## 三、按项目性格选排版

不同类型的项目应该用不同的字体和视觉气质：

### 基础设施 → 大无衬线 + Mono
**适用：** CLI工具、库、框架、DevOps工具
- 标题用：Inter、IBM Plex Sans、Roboto
- 代码/技术元素用：JetBrains Mono、IBM Plex Mono、Fira Code
- 气质：干净、直接、可靠
- 避免：衬线体、花哨的display字体
- 颜色：低饱和度，主色+灰阶为主

### 研究/数据库 → 沉稳衬线或克制无衬线
**适用：** 论文代码、数据库、数据科学工具、学术项目
- 标题用：Source Serif Pro、IBM Plex Serif、Inter（细体）
- 气质：严谨、可信、沉稳
- 避免：粗黑标题、高饱和颜色
- 颜色：深蓝、墨绿、炭黑、米白

### 编程语言 → 工业显示体 + 代码Mono
**适用：** 编程语言、编译器、解释器、类型系统
- 标题用：Space Grotesk、JetBrains Mono（大字）、IBM Plex Mono
- 代码示例是核心元素
- 气质：精确、工程感、有辨识度
- 可以用一个主色调，其他保持黑白

### 创意工具 → 开放无衬线
**适用：** 设计工具、CSS框架、动画库、生成艺术
- 标题用：Manrope、Inter、DM Sans
- 气质：灵活、有创造力、友好
- 可以展示实际生成的作品作为主要视觉
- 颜色可以更活泼，但要克制

### 文档/知识项目 → 安静可读字体
**适用：** 文档站、知识库、教程、笔记工具
- 标题用：Source Sans Pro、Inter、Merriweather
- 气质：安静、容易阅读、不打扰
- 避免：粗重的字重、强烈对比
- 文字是主角，图形是辅助

## 四、5种构图模式

### 1. Split（左右分栏）
**布局：** 左边文字，右边证明素材

```
┌─────────────────────────────────┐
│ [类别]                    [代码]│
│ [大标题]                  [片段]│
│ [描述]                    [截图]│
│ [元数据]                        │
└─────────────────────────────────┘
```

**适用：** 有清晰代码示例或终端输出的项目
**优点：** 信息层级清晰，阅读自然
**比例：** 通常4:6或5:5

### 2. Integrated（图文同网格）
**布局：** 文字和素材交错排列在统一网格中

```
┌─────────────────────────────────┐
│       [类别] [大标题]           │
│  [代码]    [描述]    [截图]     │
│            [元数据]             │
└─────────────────────────────────┘
```

**适用：** 有多个小素材可以展示的项目
**优点：** 现代感强，视觉丰富
**注意：** 网格对齐必须精确

### 3. Artifact Wall（产物墙）
**布局：** 多个真实输出物对角/错位排列

```
┌─────────────────────────────────┐
│ [生成样例1]                     │
│    [大标题] [描述]   [样例2]    │
│ [样例3]              [元数据]   │
└─────────────────────────────────┘
```

**适用：** 创意工具、生成器、UI组件库
**优点：** 直接展示"它能做出什么"
**关键：** 所有样例必须是真实输出，不要mockup

### 4. Background Proof（背景证明）
**布局：** 放大证明素材作为背景，文字叠在上面

```
┌─────────────────────────────────┐
│ ╔═══════════════════════════╗   │
│ ║ [大标题]  （代码/输出/      ║  │
│ ║ [描述]     截图 作背景）   ║  │
│ ║ [元数据]                   ║  │
│ ╚═══════════════════════════╝   │
└─────────────────────────────────┘
```

**适用：** 代码库、有标志性输出的工具
**注意：** 背景必须加足够的模糊/遮罩，保证文字可读
**遮罩：** 通常用深色+70-90%透明度，或者浅色渐变

### 5. Title-only（纯排版）
**布局：** 只有文字，没有额外图形

```
┌─────────────────────────────────┐
│                                 │
│           [大标题]              │
│            [描述]               │
│           [元数据]              │
│                                 │
└─────────────────────────────────┘
```

**适用：** 极简工具、底层库、理念先行的项目
**优点：** 自信、克制、不花哨
**关键：** 字体选择、字距、行高必须极其讲究

## 五、糖糖it推荐：各主题最佳Hero构图

根据现有主题风格，推荐最合适的构图方式：

| 主题 | 性格 | 推荐构图 | 备选 | 视觉重点 |
|------|------|----------|------|----------|
| **Blockframe** | 简洁通用、模块化 | Split | Title-only | 清晰的左右分栏，代码示例在右，文字在左 |
| **Blockframe Dark** | 暗色、专业、开发者友好 | Background Proof | Split | 终端输出/代码作半透明背景，亮色文字叠加 |
| **Blue Professional** | 商务、专业、企业级 | Integrated | Split | 规整网格排布，Logo/图标+文字+关键数据统一布局 |
| **Purple Gold Presentation** | 高端、演示感、项目展示 | Artifact Wall | Integrated | 多个项目亮点/界面截图错落排布，紫金配色点缀 |

### 各主题具体建议

**Blockframe（浅色框架）**
- 构图：经典Split，左文右图
- 字体：大无衬线标题+Mono代码
- 素材：放真实的代码片段或使用示例
- 不要加：阴影、渐变、多余装饰

**Blockframe Dark（暗色框架）**
- 构图：Background Proof
- 字体：无衬线标题+高亮Mono代码
- 素材：放大一段真实代码或终端输出作背景，加80%黑色遮罩
- 细节：用主题色高亮1-2个关键词

**Blue Professional（蓝色专业）**
- 构图：Integrated规整网格
- 字体：沉稳无衬线，所有元素对齐到网格
- 素材：Logo、一句价值主张、3个关键特性小卡片
- 气质：企业级可信赖，不要太活泼

**Purple Gold Presentation（紫金演示）**
- 构图：Artifact Wall
- 字体：现代无衬线标题，适当字距
- 素材：3-5个项目真实输出/界面截图，轻微旋转错位排列
- 点缀：金色细线分隔，紫色作为强调色
- 氛围：有展示感，但不要浮夸

## 核心原则

> **项目原生的意思是：把项目本身拿给人看，而不是给项目套一个通用模板。**

1. **素材必须真实**：不要用图库图片，不要画假的UI，就用项目自己产出的东西
2. **文字必须具体**：不说废话，一句话说清是什么
3. **排版匹配性格**：什么类型的项目就用什么气质的设计
4. **克制优于堆砌**：少即是多，能不用的装饰就不要加
5. **服务于动作**：Hero要引导用户去做那个主要动作，而不是单纯好看

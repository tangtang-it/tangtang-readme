## 一、主题选择决策树

选择主题不是凭喜好，而是让视觉语言匹配项目的受众与气质。遵循以下决策路径：

```
开始
  │
  ├─ 项目主要在夜间/深色环境使用？或与游戏/极客文化相关？
  │   ├─ 是 ─→ 开发者工具/CLI/AI/极客项目？
  │   │       ├─ 是 ─→ 赛博朋克霓虹
  │   │       └─ 否 ─→ 暗夜新野兽派
  │   └─ 否 ─→ 继续
  │
  ├─ 项目是知识付费/视频教程/精品课程？
  │   ├─ 是 ─→ 紫金高级感
  │   └─ 否 ─→ 继续
  │
  ├─ 项目涉及数据/研究/企业/咨询/专业工具？
  │   ├─ 是 ─→ 糖蓝专业风
  │   └─ 否 ─→ 继续
  │
  ├─ 项目是创意/设计/艺术/独立产品/设计师作品？
  │   ├─ 是 ─→ 糖果新野兽派（亮色）
  │   └─ 否 ─→ 继续
  │
  └─ 日常工具/教育项目/轻量库/小而美工具？
      ├─ 是 ─→ 清新薄荷风
      └─ 否 ─→ 重新审视项目定位，或询问用户偏好
```

### 决策辅助问题

当仍不确定时，回答这三个问题：

1. **谁是主要受众？**
   - 专业人士/企业 → 糖蓝专业
   - 开发者/极客 → 赛博朋克
   - 创作者/设计师 → 糖果新野兽派
   - 学习者/普通用户 → 清新薄荷
   - 学员/观众 → 紫金高级

2. **项目想传达什么感受？**
   - 可信、稳重、专业 → 糖蓝专业
   - 酷、前沿、科技感 → 赛博朋克
   - 活泼、大胆、有个性 → 糖果新野兽派
   - 高级、精致、有质感 → 紫金高级
   - 清爽、友好、易用 → 清新薄荷
   - 神秘、沉浸、夜间友好 → 暗夜新野兽派

3. **默认阅读环境是亮还是暗？**
   - 明亮办公室/白天 → 亮色主题（糖果新野兽派/糖蓝/清新薄荷）
   - 夜间/深色模式偏好 → 暗色主题（暗夜/赛博朋克/紫金）

## 二、项目类型与推荐主题

| 项目类型 | 首选主题 | 备选主题 | 理由 |
|---------|---------|---------|------|
| **CLI / 开发者工具** | 赛博朋克霓虹 | 暗夜新野兽派 | 终端感、霓虹光标、代码母题天然契合极客审美 |
| **数据 / 研究 / 分析** | 糖蓝专业风 | 清新薄荷 | 冷静、可信、数据可视化友好，传递专业可靠感 |
| **创意 / 设计 / 艺术** | 糖果新野兽派 | 紫金高级感 | 大胆撞色、不规则形状匹配创意气质，突出个性 |
| **视频教程 / 知识付费** | 紫金高级感 | 糖蓝专业风 | 深色背景+金色点缀营造精品课程的高级质感 |
| **日常工具 / 效率应用** | 清新薄荷风 | 糖蓝专业风 | 低饱和绿+白色传递清爽、易用、无负担的感觉 |
| **夜间工具 / 游戏项目** | 暗夜新野兽派 | 赛博朋克霓虹 | 高对比度亮色在深色背景上既护眼又有冲击力 |

### 边界案例处理

- **AI 产品**：如果面向开发者 → 赛博朋克；如果面向普通用户 → 清新薄荷或糖蓝
- **开源库**：根据库的定位，不默认选糖果新野兽派
- **文档工具**：糖蓝专业或清新薄荷，优先考虑可读性
- **个人作品集**：优先糖果新野兽派，体现个性

## 三、调色板定制规则

每个主题有其灵魂色组，微调是为了更好匹配项目，不是重造主题。

### 3.1 调色板结构

每个主题固定包含 5 个角色，定制时保持角色关系不变：

| 角色 | 作用 | 面积占比 |
|-----|------|---------|
| 背景色 (Background) | 画布底色 | 最大（~60%） |
| 前景色 (Foreground) | 主要文本 | 大（~25%） |
| 主色 (Primary) | 品牌识别、标题、按钮 | 中（~10%） |
| 强调色 (Accent) | 高亮、交互、链接 | 小（~4%） |
| 柔和色 (Muted) | 辅助文本、分割、次要元素 | 最小（~1%） |

### 3.2 定制自由度

| 元素 | 允许调整 | 禁止调整 |
|-----|---------|---------|
| 主色色相 | ±30° 色环偏移 | 跨色系（如从蓝变橙） |
| 主色饱和度 | ±15% | 低于 20% 或高于 90% |
| 主色明度 | ±10% | 与背景对比度低于 4.5:1 |
| 强调色 | 可选择主色邻近色或互补色 | 使用超过 2 种强调色 |
| 背景色 | 极微调色温（暖/冷偏 ±5°） | 改变明暗基调（亮↔暗） |
| 柔和色 | 随前景色微调灰阶 | 使用彩色灰替代中性灰 |

### 3.3 对比度红线

- 前景/背景对比度 ≥ 4.5:1（WCAG AA）
- 主色/背景对比度 ≥ 3:1（大文本）
- 强调色只用于小面积装饰，不承载重要文本

### 3.4 品牌色融合

如果项目已有品牌色：

1. 将品牌色映射到「主色」位置
2. 围绕品牌色调整同色系的强调色和柔和色
3. 背景和前景保持主题骨架，不大幅改动
4. 如果品牌色与主题色系冲突严重，考虑换更兼容的主题

## 四、视觉语法五要素

主题不只是颜色，是五个要素共同构成的视觉语言。

### 4.1 调色板 (Palette)

- 见第三节调色板定制规则
- 同一资产内严格遵循 5 色角色，不额外引入颜色
- 渐变只在主题明确允许时使用（赛博朋克、紫金）

### 4.2 字体 (Typography)

| 主题 | 字体风格 | 字重对比 | 字号跨度 |
|-----|---------|---------|---------|
| 糖果新野兽派 | 几何无衬线、等宽混用 | 极端（Black ↔ Regular） | 大（48px ↔ 14px） |
| 暗夜新野兽派 | 等宽为主、几何无衬线 | 大（Bold ↔ Light） | 大 |
| 糖蓝专业 | 人文无衬线、系统UI | 中等（Semibold ↔ Regular） | 中（36px ↔ 14px） |
| 紫金高级 | 衬线标题+无衬线正文 | 大（Bold ↔ Light） | 大 |
| 赛博朋克 | 等宽、未来感无衬线 | 极端（Heavy ↔ Thin） | 极大 |
| 清新薄荷 | 圆体、柔和无衬线 | 小（Medium ↔ Regular） | 小（32px ↔ 14px） |

**铁则**：
- 不引入外部远程字体（GitHub SVG 环境限制）
- 使用系统字体栈保证跨平台一致
- 代码/终端相关内容必须用等宽字体

### 4.3 形状 (Shape)

| 主题 | 圆角 | 描边 | 装饰形状 |
|-----|------|------|---------|
| 糖果新野兽派 | 0-4px，硬边为主 | 粗描边（3-6px），黑色/深色 | 几何色块、随机倾斜、粗线条 |
| 暗夜新野兽派 | 0-2px | 中等描边（2-4px），亮色 | 霓虹边框、网格、像素元素 |
| 糖蓝专业 | 6-12px，统一圆角 | 细描边（1-2px），浅灰 | 矩形卡片、细线分隔、克制阴影 |
| 紫金高级 | 4-8px，精致圆角 | 无描边或金色细边 | 光效、渐变、微妙纹理 |
| 赛博朋克 | 0px，锐利直角 | 霓虹发光描边 | 斜切角、扫描线、电路图案 |
| 清新薄荷 | 12-20px，圆润 | 无描边或极细淡边 | 柔和Blob、波浪、圆润图标 |

### 4.4 母题 (Motif)

母题是从项目本身提取的重复视觉线索，让设计看起来是项目原生的：

- **CLI 工具** → 终端提示符 `$`、光标 `▊`、命令输出、ASCII 边框
- **数据项目** → 坐标轴、网格线、数据点标签、误差线、图表碎片
- **创意工具** → 画笔痕迹、色板、图层堆叠、控制点、网格
- **视频教程** → 播放按钮、时间轴、进度条、字幕条、章节标记
- **日常工具** → 简洁图标、勾选标记、开关、柔和提示气泡
- **游戏项目** → 像素块、血条、对话框边框、8-bit 装饰

**铁则**：母题从项目功能中提取，不用通用装饰（星星、火花、随机几何）。

### 4.5 密度 (Density)

| 主题 | 留白 | 信息密度 | 元素数量 |
|-----|------|---------|---------|
| 糖果新野兽派 | 中等 | 中高 | 多，但用色块区分 |
| 暗夜新野兽派 | 少 | 高 | 多，深色背景容纳更多 |
| 糖蓝专业 | 多 | 中 | 少而精，大量呼吸空间 |
| 紫金高级 | 多 | 低 | 极少，聚焦核心信息 |
| 赛博朋克 | 少 | 高 | 非常多，信息轰炸感 |
| 清新薄荷 | 多 | 低 | 少，宽松舒适 |

## 五、糖糖it的克制规则：每个主题的 Do / Don't

### 5.1 糖果新野兽派 (Candy Brutalist)

**Do**
- 使用高饱和撞色（粉+黄+蓝典型组合）
- 粗黑描边、硬阴影、无圆角或小圆角
- 元素可以有 -2° ~ 2° 的随机倾斜
- 大标题用超粗字重，正文用常规字重形成对比
- 色块作为信息分组容器
- 保留手写感/手绘感的不完美

**Don't**
- 不要用渐变、模糊、柔光效果
- 不要加精致阴影或发光效果
- 不要让所有元素对齐到像素——故意的错位是风格
- 不要超过 4 种主色，避免变成彩虹
- 不要用圆润大圆角——野兽派是硬朗的
- 不要在浅色背景上用浅色文字

### 5.2 暗夜新野兽派 (Candy Brutalist Dark)

**Do**
- 深黑/深灰背景（#0a0a0a ~ #1a1a1a）
- 高饱和亮色作为主色和强调色
- 粗描边用亮色而非黑色
- 保留硬边、几何感、色块堆叠
- 可以加入霓虹边框但不要过度发光
- 文字必须有足够对比度

**Don't**
- 不要用过深的灰色文字——在 #121212 上至少用 #e0e0e0
- 不要大面积使用纯黑（#000000），用深灰更舒适
- 不要让亮色面积超过 30%——深色才是主体
- 不要渐变（赛博朋克才用渐变）
- 不要混用软阴影
- 不要降低对比度追求"高级灰"

### 5.3 糖蓝专业风 (Sugar Professional)

**Do**
- 蓝色系为主色（从深蓝到天蓝都可）
- 大量留白、统一圆角、克制分隔线
- 清晰的信息层级，标题→副标题→正文明确区分
- 图表使用柔和但可区分的配色
- 卡片式布局，微阴影或无边框
- 数据、表格、代码块要清晰易读

**Don't**
- 不要用高饱和撞色——专业风是克制的
- 不要倾斜元素或使用随机位置
- 不要用超过 1 种强调色
- 不要加装饰性几何形状——每个元素都要有目的
- 不要让标题过于巨大——专业风不需要喊
- 不要用等宽字体作为标题字体

### 5.4 紫金高级感 (Purple Gold Premium)

**Do**
- 深紫/深靛蓝背景（#1a1025 ~ #0f0a1a）
- 金色/香槟金作为强调色（#d4af37 ~ #f5d78e）
- 精致排版，大标题+稀疏行距
- 可以使用微妙的金色渐变和光效
- 衬线字体用于标题增加高级感（系统可用的衬线）
- 大量留白，聚焦核心信息

**Don't**
- 不要用霓虹或荧光色——高级感不是廉价发光
- 不要塞太多信息——这个主题是"少即是多"
- 不要用纯黄替代金色——金色是低饱和的暖黄
- 不要用粗描边或硬边框
- 不要在紫色背景上用紫色文字——对比度！
- 不要加入可爱或卡通元素

### 5.5 赛博朋克霓虹 (Cyberpunk Neon)

**Do**
- 深色背景（#0d0221 ~ #0a0a12）
- 霓虹色：品红 (#ff00ff)、青色 (#00ffff)、黄色 (#ffff00)
- 发光效果（SVG filter 实现）
- 锐利直角、斜切角、网格线
- 等宽字体、终端风格
- 扫描线、电路图案、故障效果（glitch）元素
- 高密度信息排布

**Don't**
- 不要用圆角——赛博朋克是锐利的
- 不要用柔和颜色或马卡龙色
- 不要用衬线字体
- 不要大量留白——赛博朋克是拥挤的未来感
- 不要让霓虹色面积过大——发光是点缀不是主体
- 不要用真实照片或写实素材（除非混合合成模式）

### 5.6 清新薄荷风 (Fresh Mint)

**Do**
- 薄荷绿/鼠尾草绿为主色（#98ff98 ~ #7cb342 范围的柔和绿）
- 白色或极浅灰背景
- 圆润大圆角（12-20px）
- 柔和阴影或无阴影
- 宽松间距、舒适行高
- 圆体或柔和无衬线字体
- Blob 形状、波浪线等柔和装饰

**Don't**
- 不要用高饱和颜色——薄荷是柔和的
- 不要用黑色文字——用深灰（#333333 ~ #444444）
- 不要用粗黑描边
- 不要高密度排布——要呼吸感
- 不要用硬几何形状
- 不要加发光、霓虹、渐变等强烈效果
- 不要使用斜体或过于艺术化的字体

## 六、排版模式

根据展示内容选择合适的排版模式，而不是所有内容都塞进同一个 Hero。

### 6.1 Artifact Wall（产物墙）

**适用场景**：展示 CLI 输出、截图集合、多个设计案例、功能预览

**特征**：
- 多个产物（截图/输出/卡片）以网格或自由排布方式陈列
- 产物之间有微妙的重叠、旋转、缩放变化，营造物理感
- 标题和价值主张在墙之上或融入墙中
- 产物之间留白要足够，避免拥挤
- 用投影或边框区分每个产物层级

**布局要点**：
```
┌─────────────────────────────────────┐
│  大标题                              │
│  一句话价值主张                       │
│                                     │
│  ┌──────┐  ┌────────────┐           │
│  │ 产物1 │  │   产物2    │  ┌────┐   │
│  │      │  │            │  │产物3│   │
│  └──────┘  │            │  └────┘   │
│            └────────────┘           │
│               ┌──────┐              │
│     ┌────┐    │ 产物4 │              │
│     │产物5│    └──────┘              │
│     └────┘                          │
└─────────────────────────────────────┘
```

**主题适配**：所有主题都适用，糖果新野兽派和赛博朋克效果尤佳。

### 6.2 Before / After（对比展示）

**适用场景**：展示工具效果、转换前后、优化对比、代码重构

**特征**：
- 左右或上下两栏明确分隔
- "Before" 用低饱和或灰度处理，"After" 用主题主色
- 中间用箭头、分隔线或 VS 标记连接
- 两栏视觉重量要平衡，但 After 可以稍突出
- 标注关键差异点

**布局要点**：
```
┌──────────────────┬──────────────────┐
│     BEFORE       │      AFTER       │
│                  │                  │
│  [旧的样子]      │  [新的样子]      │
│  灰度/低饱和     │  全彩/高亮       │
│                  │                  │
└──────────────────┴──────────────────┘
          ↓ 关键改进点标注
```

**主题适配**：糖蓝专业（数据对比）、清新薄荷（易用性改进）效果最佳。

### 6.3 System Map（系统地图）

**适用场景**：架构图、工作流程、生态系统、模块关系

**特征**：
- 节点+连线的清晰关系图
- 节点用统一形状（主题适配的卡片/圆角/直角）
- 连线有方向、有标签说明关系
- 从左到右或从上到下的阅读流
- 分组用背景色块或边框
- 足够留白避免连线交叉混乱

**布局要点**：
```
┌─────┐     ┌─────┐     ┌─────┐
│  A  │────→│  B  │────→│  C  │
└─────┘     └─────┘     └─────┘
   │                       ↑
   └────────→┌─────┐───────┘
             │  D  │
             └─────┘
```

**主题适配**：糖蓝专业最适合（架构图需要专业可信感），赛博朋克可用于技术系统。

### 6.4 Annotated Specimen（标注样本）

**适用场景**：展示核心功能、组件预览、设计系统展示、API 示例

**特征**：
- 一个放大的核心产物/组件作为主体
- 用引出线（leader line）标注关键部分
- 标注文字简洁，解释"这是什么"和"为什么好"
- 主体居中或偏左，标注围绕分布
- 标注顺序遵循视觉流，不要杂乱交叉

**布局要点**：
```
     标注1 ──┐
             ↓
┌────────────────────────┐
│                        │
│    ┌──────────┐        │ ←── 标注2
│    │ 核心样本  │        │
│    └──────────┘        │
│         │              │
└─────────┼──────────────┘
          ↓
        标注3
```

**主题适配**：所有主题，紫金高级（精品细节）和糖蓝专业（功能说明）尤其适合。

### 6.5 Sequence Strip（序列条带）

**适用场景**：步骤教程、快速开始流程、时间线、安装过程

**特征**：
- 水平或垂直排列的步骤序列
- 每个步骤有编号、标题、简短说明、可选小图
- 步骤之间用箭头或连接线串联
- 3-5 步最佳，不超过 7 步
- 步骤视觉权重一致，当前步骤可高亮

**布局要点**：
```
┌────┐    ┌────┐    ┌────┐    ┌────┐
│ 1  │───→│ 2  │───→│ 3  │───→│ 4  │
│安装│    │配置│    │运行│    │完成│
└────┘    └────┘    └────┘    └────┘
```

**主题适配**：清新薄荷（入门友好）、糖蓝专业（清晰流程）最适合。

### 模式选择指南

| 你想展示什么 | 首选模式 |
|-------------|---------|
| 多个功能/截图/案例 | Artifact Wall |
| 效果/改进/变化 | Before / After |
| 架构/流程/模块关系 | System Map |
| 核心功能特写+解释 | Annotated Specimen |
| 快速开始/步骤/时间线 | Sequence Strip |

可以组合使用：比如 Hero 用 Annotated Specimen 展示核心，下面接 Sequence Strip 做快速开始。但不要在一个视觉资产里塞超过两种模式。

## 最后：主题是服务，不是主人

主题是让项目气质更鲜明的工具，不是必须死守的教条。当项目有强烈的自身性格时：

1. 优先保持项目识别度，主题作为框架而非枷锁
2. 微调调色板和母题，让主题适配项目而非反过来
3. 如果六套主题都不完全匹配，选择最接近的一套做定制
4. 克制永远比花哨更难——少即是多

**糖糖it的核心原则**：设计看起来是项目原生的，而不是套用了某个模板。去掉仓库名，这个 Hero 不应该能复用于无关项目。
